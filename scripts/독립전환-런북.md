# SmartHML 독립 전환 런북 (D-day Cutover)

> 목적: 기존 .NET 프로그램(레거시 SQL)에서 SmartHML로 **완전 독립**하는 날의 절차.
> 전환 후에는 **SmartHML이 유일한 원장(source of truth)** 이 되고, 레거시→SmartHML 동기화는 중단한다.
> 대상일: **2026년 9월 1일(예정)** — 실제 날짜는 담당자 확정.

---

## 0. 사전 점검 (D-1, 전날)

- [ ] SmartHML 계정·권한 최종 확인 (사용자관리 탭에서 실계정 상태)
- [ ] 단가 최신본 반영 여부 확인 (단가관리 탭)
- [ ] 거래처·제품·기사 마스터 최신 여부 확인
- [ ] 사일로 연동 정상 여부 확인
- [ ] 전날까지의 정산 **확정**(정산관리 → 정산 확정) 처리

## 1. 레거시 사용 종료 (D-day 아침)

- [ ] 현장/사무실에 **기존 프로그램 입력 중단** 공지
- [ ] 레거시에서 마지막으로 입력된 출하 건 시각 기록 (컷오버 기준점)

## 2. 마지막 전체 동기화 (레거시 → SmartHML)

레거시의 마지막 데이터까지 SmartHML로 넘긴다. 동기화 PC에서:

```bat
cd C:\SmartHML\web-app
node scripts\sync-mysql-to-supabase.mjs
```
> 플래그 없이 실행하면 **전체(full) 모드**로 전 구간을 동기화한다. (`--delta`는 증분 전용)

- [ ] 로그(`logs\sync-YYYYMMDD.log`)에서 `동기화 완료! exit=0` 확인
- [ ] 출하/단가/성적서 건수 이상 없음 확인

## 3. 동기화 중단 (스케줄러 정지)

관리자 권한 명령프롬프트에서:

```bat
C:\SmartHML\web-app\scripts\disable-sync.bat
```

- [ ] `SmartHML_Sync_10min` / `SmartHML_Sync_Hourly` / `SmartHML_Sync_1900` **모두 Disabled** 확인
- [ ] (원장 이중화 방지) 이 시점 이후 레거시→SmartHML 자동 upsert가 더 이상 SmartHML 데이터를 덮어쓰지 않음

> ⚠️ 중요: 독립 후에는 SmartHML이 원장이다. 동기화를 계속 켜두면 레거시(빈/오래된 데이터)가
> SmartHML을 덮어쓸 수 있으므로 **반드시 중단**한다.

## 4. 전환 검증

- [ ] SmartHML에서 신규 출하 1건 등록 → 출하증 발급까지 정상
- [ ] 배차·계근·출하확정 흐름 정상
- [ ] 정산관리에서 당일 집계 정상
- [ ] 운송사 계정 로그인 → 본인 데이터만 노출 확인

## 5. 정리 (D+7 이후, 안정화 확인 후)

- [ ] 동기화 스케줄러 **완전 삭제** (선택):
  ```bat
  schtasks /Delete /TN "SmartHML_Sync_10min"  /F
  schtasks /Delete /TN "SmartHML_Sync_Hourly" /F
  schtasks /Delete /TN "SmartHML_Sync_1900"   /F
  ```
- [ ] 동기화 PC의 절전 금지 설정 원복 가능 (더 이상 상시 가동 불필요)
- [ ] `.env.local`의 `MYSQL_*` 접속정보는 보존(감사/이력 대비) 또는 제거 결정

## 롤백 (문제 발생 시)

전환 직후 심각한 문제가 있으면 레거시로 임시 복귀:

1. 현장에 기존 프로그램 재사용 공지
2. 동기화 재가동:
   ```bat
   schtasks /Change /TN "SmartHML_Sync_Hourly" /ENABLE
   schtasks /Change /TN "SmartHML_Sync_10min"  /ENABLE
   ```
3. SmartHML에서 컷오버 이후 입력한 건은 수기로 레거시에 반영(건수 적을 때)

> 단, SmartHML에서 이미 다량 입력이 이뤄졌다면 롤백은 데이터 정합성 위험이 크므로
> 롤백보다 **SmartHML에서 문제 수정**을 우선한다.

## 참고 — 동기화 방향/우선순위

- 전환 **전**: 레거시 SQL = 원장. 동기화는 레거시 → SmartHML (upsert 덮어쓰기).
- 전환 **후**: SmartHML = 원장. 동기화 **없음**.
- 관련 메모: `sync-scheduler-ops` (시간당 동기화는 이 PC 로그인 상태에서만 동작, bat는 ASCII 전용)
